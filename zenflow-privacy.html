ZenFlow AI — privacy notice

Updated: 24 November 2026

This notice describes the current ZenFlow AI hackathon application, developed by Salah Eddine Louffidi (LOUFFI Edition).

Purpose and Jira access

ZenFlow is intended for personal triage of Jira work. In Jira mode, its Forge resolver runs as the signed-in user, uses the read-only read:jira-work scope, and reads assigned open issues that the user is permitted to access. The dashboard reads issue keys, summaries, priorities, due dates and status. ZenFlow uses these fields to display tickets, organize them in the visual interface and provide local rule-based suggestions.

ZenFlow does not change Jira issue records. The Do Now, Later and Archive queues are personal application preferences.

Browser storage

ZenFlow stores display settings and personal queue decisions in browser local storage. In Jira mode, the storage key contains the Jira site identifier and the signed-in user's account identifier. Stored queue preferences include Jira issue keys and their selected dispositions. The application does not have a separate server-side database for these preferences. Local preferences remain in the browser until the site data is cleared or the browser removes them. Users can clear the app's local data through their browser.

Ticket details and AI results are held in the active page's memory. The current application does not persist AI responses in its browser preference storage. Normal hosting, infrastructure and provider logs may be subject to their own processing and retention policies.

Optional TypeSafe Jev analysis

When the app owner enables Jev and a user explicitly selects Analyze with Jev, the server checks the selected issue's assignment and the user's Jira access again. It sends the issue summary, priority, due date and current date to TypeSafe at api.typesafe.ai, along with instructions for the triage recommendation. Summaries can contain personal or sensitive business information. Users should request AI analysis only for tickets their organization permits to be processed by this external service.

The Jev request does not include an issue description, attachment, comment, Jira account identifier or issue key in its request payload. The app owner's TypeSafe API credential is used by the server to authenticate the request and is not shared with the browser.

TypeSafe processes AI requests under its own terms, configuration and privacy policies. See TypeSafe's privacy policy and data use and retention information. The current ZenFlow implementation does not independently verify a customer's TypeSafe retention settings or guarantee deletion by the provider.

Jev recommendations are advisory. Users decide whether to act on them. Rule-based triage and visual controls work without requesting Jev analysis.

Local demo

The standalone local demo uses synthetic tickets and example recommendations. It does not connect to Jira or contact the TypeSafe API. Demo display and queue preferences are saved in browser local storage.

Questions and requests

For questions about ZenFlow's processing or requests related to the app, use the support contact provided on the Forge installation page when available. For source review, contact the repository owner through the existing project communication channel. Include only the information needed to address the request; do not send API keys or confidential Jira content in a public issue.

Atlassian platform processing and account data are also subject to the Atlassian privacy policy.
